# Council independent review — backend (Opus, 2026-09-26)

Verdict: **needs_changes**. Architecture and domain modelling sound; household scoping consistent; cook mode enforced centrally; one permission table; optimistic locking; timezone handling; LLM calls bounded. Test suite broad but SQLite-only.

## Critical
- **C1 Admin image cannot build.** `.dockerignore` re-includes only `admin/main.py` and `admin/catalogue_admin.py`; `admin/Dockerfile:23` also copies `kitchen_admin.py` and `pantry_admin.py`. Reproduced: `"/admin/kitchen_admin.py": not found`. nginx depends on admin healthy → whole stack down. Fix: add `!admin/kitchen_admin.py`, `!admin/pantry_admin.py` (or `!admin/*.py`); CI `docker compose build`.
- **C2 Nightly purge fails on Postgres every run.** `workers/worker.py:128` sets `phone=f"deleted:{uid}"` (44 chars) into `users.phone String(20)` (`models/identity.py:19`). StringDataRightTruncation rolls back the whole purge → nothing is ever hard-deleted (FR-A8/DPDP). Fix: short tombstone or nullable phone + flag; run suite on Postgres.
- **C3 No valid production configuration; obvious workaround is insecure.** OTP providers other than dev raise NotImplementedError (`services/otp.py:31`) after rate-limit counters are consumed → 500 on every login in prod; `StoreApiVerifier` always 503 → every household read-only after 7 days; `FcmPush.send` only logs. `config.py:82` allows `STORE_VERIFIER=fake` in prod → any string activates a subscription, `/v1/webhooks/appstore` accepts unsigned JWS, `appAccountToken` resolved as household id → forged REVOKE/SUBSCRIBED for any household. Fix: validator refuses fakes/unverified JWS outside dev/test; ship MSG91, Play/App Store verification, x5c JWS, FCM or gate launch.

## High
- **H1 Worker sweeps stall at scale; one failure stops all households.** `run_all`/`kitchen_sweeps` one transaction across all households (`worker.py:383-403`); `send_tomorrow_tickets` scans every household every 5 min 20:00–24:00; inbox dedupe on `(household_id, event, created_at)` unindexed; `subscription.sweep` one query per row; no `FOR UPDATE`, StaleDataError aborts the cycle; ARQ default job_timeout 300 s → cancelled every cycle silently. Fix: per-ticket/household transactions, `with_for_update(skip_locked=True)` + LIMIT, `notification_marks` table, index, explicit job_timeout, failure metric.
- **H2 OTP open to SMS pumping and targeted lockout.** `auth.py:54-78,158-165`: per-number + client-supplied device id only; no per-IP/global limit; nginx no limit_req; 3 wrong codes lock the victim's phone for 10 min repeatedly; `otp.attempts` never read; concurrent correct verifies both succeed. Fix: nginx limit_req on /v1/auth, per-IP/global counters, lock scoped to phone+IP/device with backoff, Play Integrity/App Attest, consume OTP with `UPDATE ... WHERE consumed_at IS NULL RETURNING`.
- **H3 Allergen safety relies on exact free-text matches (F-5.2-03 not closed).** Member allergens are free `Tags` (`schemas.py:247`), lowercased only member-side (`services/catalogue.py:66`); ingredient allergens un-normalised on import (`importer.py:202`); exact set intersection (`engine/rules.py:43`); `Allergen` enum (`models/enums.py:77`) unenforced. Fix: `allergens: list[Allergen]` + `allergens_other` (warn only); normalise/validate on import and admin; CHECK/test.
- **H4 No TLS; admin exposed.** Prod publishes only 80; no 443 block; admin cookie `https_only=not IS_DEV` (`admin/main.py:206`) → login impossible over HTTP; `X-Forwarded-Proto $scheme` (`nginx.conf:47`) overwrites LB value; `/admin` public with one shared password, no lockout/2FA/audit, full write on Users/Subscriptions/Cooks bypassing invariants. Fix: certbot/443 + HSTS, pass through `$http_x_forwarded_proto`, IP allowlist/basic-auth + limit_req on /admin, per-staff accounts + TOTP + audit.
- **H5 "One household / one purchase" only in app code.** No partial unique index on active membership per user (`household.py:129`); `active_membership` `.limit(1)`; DELETE household → POST households → restore yields two households and `MultipleResultsFound` 500 in `cooks.py:136`; `Cook.phone` not unique; `purchase_token`/`original_transaction_id` not unique (`household.py:419-420`) → webhook 500 + infinite Pub/Sub retries; no IntegrityError handler (`core/errors.py`) → 500 on unique races. Fix: partial unique indexes; IntegrityError → 409; restore refuses if another active membership exists.

## Medium
- M1 Postgres untested (SQLite, FK off): varchar limits, RESTRICT on `recipe_ingredients.ingredient_id` (`catalogue.py:185`), cascades, CHECK enums, JSONB, pgvector (needs superuser on managed PG). Fix: CI job on `pgvector/pgvector:pg16` running upgrade + suite + downgrade/upgrade round-trip.
- M2 Idempotency middleware caches all <500 responses 24 h (`core/middleware.py:177`) incl. 429/409/402 and `/auth/verify` bodies with tokens under "anon"; Redis down → 500 on every keyed POST. Fix: store 2xx + deterministic 4xx only; skip /v1/auth/*; fail open.
- M3 Refresh rotation has no grace window (`auth.py:195-200`) → parallel refreshes on app resume revoke the session. Fix: accept previous jti 30–60 s or return same pair.
- M4 Hot paths hydrate the whole catalogue per request (`recommendations.py:87`, chat `pipeline.published()`); DB session held across the LLM call; pool 10+10 × 2 workers; connection budget 80/100. Fix: in-process catalogue snapshot keyed by max(updated_at); release session before LLM; ranking off the loop.
- M5 `GET /v1/tickets` without date returns everything with N+1 (`api/tickets.py:96-122`). Fix: require range or paginate.
- M6 Exports: state-changing GET (`billing.py:170`), no rate limit, files never expire, API image never creates `/srv/media` (volume ownership risk). Fix: POST, one pending job per household, TTL cron, mkdir/chown in API image.
- M7 Push sends inside the request transaction before commit (`notifications.py:412-456`). Fix: outbox table + ARQ fan-out after commit.
- M8 Secrets/logging: dev DB password default in `x-backend-env`; prod db does not require POSTGRES_PASSWORD; Redis no auth; Play secret via `?token=` (`billing.py:76`) logged by nginx `$request_uri` (`nginx.conf:17`). Fix: `:?` for every prod secret; header-only or OIDC JWT; log `$uri`.
- M9 Deletion orphans: sole admin DELETE /me leaves adminless household (`me.py:87-95`); hired cook deleting account keeps Cook row/phone/tickets; `check_phone_free` (`cooks.py:115-122`) counts cooks in soft-deleted households; otp_requests/auth_sessions/inbox never purged.
- M10 Stuck tickets in new/unassigned never close; `sweep_no_show` no lower bound (`ticket_timers.py:103-114`) → alerts on all historical tickets after an outage.

## Low
`/v1/openapi.json` exposed in prod (`main.py:587`); `/v1/health/ready` unused by healthchecks; backups on the same VM volume; `JWT_SECRET` doubles as HMAC key for OTP/invite/refresh hashes (`security.py:30-33`); cook-invite acceptance skips cross-household phone check (`invites.py` ~160); malformed `notificationType` → `int()` 500 (`subscription.py` ~410); `menu.due_at` may be on a different day than `menu.date` (`menus.py:452`); `POST /devices` moves a token to the last registrant.

## Hidden assumptions to confirm
One hired cook per household / one household per cook phone (cooks serve 3–5 homes; a cook cannot have her own family account since create_household returns 409); admin never leaves (no transfer/multi-admin); empty households → 0 servings tickets; expired plan leaves stock/ration/member/invite writes open and hired cooks can read billing state; deleted households block the cook's phone for 7 days.

## Suggestions
Postgres CI + compose build CI first; DB constraints behind every "one per" rule; per-entity idempotent worker jobs with row locks and dedupe; launch checklist enforced in Settings (refuse fakes, unverified JWS, noop push, empty webhook secrets, default DB passwords); nginx TLS + limit_req + gzip + `$uri` + admin allowlist.
